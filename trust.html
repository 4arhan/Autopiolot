§ 03 · Security architecture

How AI agents are sandboxed, credentials vaulted, and outputs logged.

AI automation means giving a non-human actor access to systems that used to be behind a human's fingertips. The whole architecture is built so that actor can't do anything you didn't approve, and can't touch anything you didn't scope. Six load-bearing controls, in plain English.

— 01 · Runtime isolation

Agents run in per-tenant sandboxes.

Every agent execution is a short-lived container with no persistent disk, no outbound internet by default, and no shared memory with other tenants. Blast radius is one run, one tenant, one task.

How we prove itContainer images, IAM policies and network rules are versioned in public IaC. Our SOC 2 audit tests tenant separation quarterly with synthetic attacks.
— 02 · Credential vault

Your keys never sit in a prompt.

Integrations (EHRs, CRMs, ERPs) are connected via OAuth or a vaulted secret in our HSM-backed KMS. Agents request a short-lived token for a single call and the raw secret is never in the model context.

How we prove itEvery credential fetch is logged with actor, purpose, expiry, and scope. We can export the trail as a CSV for your audit team any time.
— 03 · Tool allow-listing

Agents can only call what you approved.

At deploy time, each agent is bound to a signed manifest of tools, endpoints, and max-effect thresholds. An agent asking to hit an un-listed tool is refused by the runtime — not by a prompt.

How we prove itManifests are hashed on sign, checked on every call, and diffable between versions. Nothing moves without a changelog.
— 04 · Output audit log

Every decision, logged and replayable.

Agent outputs are written to a tamper-evident append-only log with the full input, model, tool calls, and reasoning trace. You can replay any run, any time, to understand why an action was taken.

How we prove itLog integrity is checked by a separate control plane — inserts are signed, and gaps trigger an alert inside 30 seconds.
— 05 · Human-in-the-loop

High-impact actions wait for a human.

Any action above a configurable blast-radius — refunds above A$X, outbound communications, schema changes — routes to a queue for human approval before the agent is allowed to complete.

How we prove itThresholds are defined per workflow, signed by both parties, and versioned. Overrides are logged and flagged in the weekly ops report.
— 06 · Model hygiene

We pin models, you see the version.

Model versions are pinned per workflow. Upgrades are opt-in with a side-by-side benchmark. We don't silently swap a frontier release under a workflow that was approved on a prior one.

How we prove itEvery outcome in the ops console carries the model tag, the manifest hash, and the agent version that produced it.
